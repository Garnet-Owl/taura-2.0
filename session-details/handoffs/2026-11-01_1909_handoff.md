## Status
Milestone: public-model serving/UX hardening (not a training milestone). Implemented auto-fetch-on-startup for the deployed FastText and Marian models, removed manual `hf download` + copy steps, and made the local deployed copy singular (no `run_*` versioning for serving). Also closed a UI/API gap: the web UI now disables Retrieval and Word-by-Word (not just Neural) when their models aren't actually loaded. All 324 tests pass; ruff check/format clean on touched files.

Answered the user's question on HF versioning: we do **not** hand-maintain a version tag/number on the Hugging Face repo. `app/shared/model_sync.py` compares the Hub repo's own commit SHA (via `HfApi().model_info(repo_id).sha`) against a local marker file (`.hf_revision.json` inside each deploy dir) and only re-downloads when it changed — this can't be forgotten the way a manual tag bump could, and needs no write-scoped HF token to check. Each refresh still just overwrites `main` (as before); we don't keep multiple published versions on HF (git history on the Hub retains old commits anyway, so nothing is lost by not curating copies ourselves). Recorded this as owner rules in CLAUDE.md under "Machine Learning & Data Preprocessing".
